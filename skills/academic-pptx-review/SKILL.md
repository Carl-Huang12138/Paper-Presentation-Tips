# 学术汇报 PPTX 润色审阅

先读对，再判断是否值得改。保留有效页面；必要问题给有来源的局部或结构方案。本阶段只分析和报告，不改输入 PPTX。


## 通用包与宿主能力

`<SKILL_DIR>` 是当前加载的完整 Skill 文件夹（含此 SKILL.md、scripts/ 和 references/），执行时替换为该文件夹的实际绝对路径；输入和输出也使用用户指定的绝对路径。资源从 Skill 所在目录解析，不要求在原仓库或特定工作目录启动。

使用宿主实际提供的文件读取、命令执行和图片查看工具，不依赖特定工具名、斜杠命令或某个模型。图片查看须将图像提供给具备视觉能力的审阅者；读取文件名、哈希或 OCR 文字不能冒充看图。缺少命令执行/渲染/视觉能力时保留已完成部分，列出无法检查的页面和核心阻塞项，不能声称完整审阅。需要安装或接入方法时阅读 [框架使用说明](references/frameworks.md)。

## 1. 准备同一快照的读取资料

阅读包内 [11 条建议](references/presentation-tips.md)，在原仓库内使用时也阅读仓库 README；仓库之外无需原仓库。识别实际汇报、设计示例集合或用途未知。初次审阅先看原材料，正反标签、旧答案、回归案例和生成脚本不作为诊断依据；示例相邻页不自动构成连续报告。

默认按现场学术讲解审阅。明确用途可来自用户任务、材料说明，或页面中面向制作者的填写/版式指导语，须记录具体来源。设计示例里的研究内容页仍检查被展示的讲解任务；直接讲解组件职责、怎样填写内容的页面按版式教学判断，不把指导语当作正式研究汇报漏填。仅有正反标签不是用途或质量证据；分不清指导页与未完成草稿且会改变结论时给针对性确认。用途未知不能凭想象的“也可作讲义”豁免已观察到的讲解障碍。

运行 `python "<SKILL_DIR>/scripts/analyze_pptx.py" INPUT.pptx --out NEW_OUTPUT_DIR`，按 `review_packet/README.md` 逐页核对整页 PNG、简明对象视图和必要的原媒体/局部。工具路径、DPI 与字段见[使用说明](references/usage.md)。准备资料只生成待核对线索，不等于已经看图。正式导入默认复用已看过的快照；重渲染须用新目录和新审阅记录。

先选择含主要语言、公式/符号、主图与动态字段的代表页实际看 PNG，预检字形和主体是否显示，再逐页核对。`render.status=ok`、页数/哈希一致和 PDF 文本 matched 不证明 PNG 字形被绘出。中文或核心符号/主图缺失时列出受影响页、`render_fidelity` 与阻塞项，保留 partial/failed；不能把缺字图中的空白判为作者内容缺失。动态日期与缓存不同但正常可见时记录来源，不自动判缺失。

- 逐页对照标题、正文、段落/单元格、图表、图片、组合及叠层对象。记录对象或区域→实际内容→上下/左右、分组及证据归属；标题回退仅是候选，必要时按画面确认。
- 区分 slide/layout/master/theme 与 raw XML 等来源，核对有效可见性、原页号和渲染映射。备注及未显示内容不作放映画面证据。核心区域缺图、错页或映射未确认时保留未完成状态。
- 遇到图片对象，须调用图片查看工具检查整页和必要的局部细节，并将可辨认内容写入审阅记录。不得仅因对象类型为图片就判定内部内容未知。精确数值、近似读图值和无法辨认项须分别标注。
- 看完局部或原图须返回整页，核对 crop、旋转、透明度、组合变换和前景遮挡。截图用页面坐标；变换尚未支持时记录边界，不能拿局部坐标误截图区。原图完整不证明放映画面完整，素材未显示部分不作页面证据。
- 每个可见图片填写 `media_reviews`，记录 `importance=core/secondary`、读取状态、来源、置信度、可辨认内容和具体未读项。清晰印刷值、按可读尺度估值、无法辨认项分别记录；无尺度只描述趋势。照片没有文字、无法恢复逐点数据都不等于读取失败。
- 清单漏读但 PNG 可读的主体用 `structural_limitations` 说明，并以实际区域/raw XML 来源补证。抽取、继承或变换盲区属于读取能力边界；视觉读清不等于获得可编辑结构、原始数据或准确字号。

分别填写 `review_completion=complete/partial/failed` 与 `quality_status`（`status` 同值）。核心证据未检查时，只能“未完成”或“需要人工确认”，`basis` 说明已检查范围；不能完整判好或判坏。将影响主旨、主要比较或核心逻辑的具体未知列入 `blocking_unknowns`。

完成度指本次读取与审阅覆盖，不是改稿或论文核验完成度。已读清的直接冲突可以完整记录必要问题，即使正确修法仍需作者核定；未提供论文不自动使审阅 partial。

次要脚注未知可以非阻塞，说明为何不影响本页任务，不制造作者缺陷。core 图片的 partial 默认阻塞；只有 `unreadable_scope=secondary`、无 `blocking_unknowns`、具体 `nonblocking_reason`，且核心内容已识别时才能例外。secondary 的 partial 也要解释非阻塞理由；尚未查看须如实记 not_reviewed。

## 2. 先整体判断，再用 11 条提示复核

每页在筛选问题前写四项 `assessment`：`core_message`（作用与主旨）、`content_organization`（分组、先后、详略与衔接）、`visual_structure`（主次、图文、留白与协调）、`reading_path`（解释和证据如何连接）。整套写 `deck_assessment`：目标、问题—方法—证据—结论链、视觉系统与优先项。

先在正常整页视图判断阅读任务，再用局部读清细节。放大后能辨字只说明内容可读取；若讲述依赖的主要表格、图内标签或公式显著小于正文，听众难以同步找值、比较或连接证据，应记录具体可读性障碍并给保留材料的放大/重组方案。原生字号可作辅助证据，但不以固定字号阈值自动判坏，不强迫次要细节与标题同大。

逐页填写 11 项 `tip_checks`，记录 adequate / problem / not_applicable / uncertain 及实际依据。它们是检查提示，不能打分或要求产生问题。

每个适用项先确定听众要完成的任务：识别主旨、理解机制、找比较、连接证据或记住结论。adequate 的短依据说明实际阅读路径如何完成任务，例如“先见结论，下面标出的数据支持它，时间代价也保留”；只列内容或说“文字可辨、无遮挡、同一研究”没有回答理解任务。把重点埋在长段、主比较需自行搜索、说明与图反复往返等观察转为可定位障碍与收益，不能只因还能通读就降为 optional。

| 建议 | 检查的问题 |
|---|---|
| 1 字数 | 信息量或重复细节是否挤压主旨、迫使主体缩小？ |
| 2 一个核心任务 | 各部分服务同一任务，还是竞争任务需要重组？ |
| 3 标题 | 能定位内容且与正文吻合，连续页有推进吗？ |
| 4 色彩 | 层级、语义、对比与整体是否协调？ |
| 5 布局 | 分组、对齐、留白、重心与图文比例是否支持阅读？ |
| 6 案例引出问题 | 引入是否直观，前页是否已有案例？ |
| 7 例子与公式 | 技术内容有足够导读吗？解释可在前页，不强制配图。 |
| 8 创新点 | 做法与价值是否简洁、有层级？ |
| 9 突出重点 | 主结论、关系或数据能否定位，主体是否清晰协调？ |
| 10 图表表达 | 能方便比较与读出结论吗？表格可以有效。 |
| 11 总结 | 收尾是否回扣问题、方法和结果？结合此前总结判断。 |

“无遮挡”只是读取检查；“纯文字、同权、留白、多部分”也只是观察。根据页面任务判断具体关系和阅读路径。清晰观点页、技术听众的公式页、同一任务的概览、有效高亮表与已有总结的 Q&A 均可保留。不以填满页面、丰富组件或统一成流程图为目标。

“同一研究”只是主题一致，概览仍须有一条可跟随的观察→问题或方法→结果路径。贡献页要能快速说出做法与价值；完整表可以查证，但现场主比较须有导读或可定位的关键行列；多图页要能把短主张与各自证据、限定条件对应。优先提炼/近邻标注/同页重组，奏效时保留原类型，不强制换图或拆页。以“前页讲过”“附录/专家复习”改变判断时引用具体页的已读内容或用户用途说明，找不到就提出会影响结论的针对性确认。

## 3. 分清必要、可选与待上下文确认

- `issues` 只收 `recommendation_kind=necessary`：已有可定位障碍，能说明 `obstacle` 与 `benefit`。高为核心不可读、缺失或直接矛盾；中为明确的主要结构/阅读障碍；低为真实的局部阅读影响。无需证明严重误读，但不能仅凭另一种版式更漂亮判现页有问题。
- 判断必要性的三项依据是：障碍能定位、影响本页实际讲解任务、改动有明确理解收益。三项成立时列必要修改；纯审美偏好或另一种结构也有效时留可选。先完成表达组织诊断，再补重要局部逻辑/事实问题，不以数学核对替代润色判断。
- `optional_suggestions` 写 `recommendation_kind=optional` 与 object/evidence/direction/benefit，不改变质量状态，不凑数；没有必要问题且核心检查完成时可以“无需修改”。可读换行、轻微不对称、字形规范化和空白本身不进 issues。
- `context_questions` 写 `recommendation_kind=needs_context`、具体 `evidence` 和可执行 `action`，说明材料目的、听众或已有说明如何影响判断。只保留会改变结论或修法的未知；不因未全面复证论文、不知肖像身份或缺外部核验而例行制造疑点。
- 比较总句可能概括前页，当前图可能只放其中一组。先确认播放范围及可引用的前页证据；不要仅凭当前图例较窄就否定整套结论。上下文未明时给条件式确认，已有证据支持的总句应保留；图例解释可作为可选改善。
- 表达组织用 scope=presentation；有证据的重要局部逻辑/事实冲突用 critical_logic / factual_error。先核对已读清的核心公式、单位、图例、比较范围及同研究的前后页；明确冲突可记录，正确版本未知时保留核对方向，不任选一个修法当答案。同一跨页冲突设一个主记录，其余页引用。

数值举例、修改后的复算与新增比较结论用计算工具。逐输入保留真实来源或明确标 `test_assumption`，不把合法代入当实验数据或原论文全部假设。并列、例外、单位和比较范围必须保留；算术正确不证明来源正确。

围绕本页实际使用的主比较核对极值、并列和明显例外，记录具体行/组及显示值，不扩成逐格论文事实审查。局部例外不否定已有主趋势；若原句范围不明，给局部限定或针对性确认，不强行把总体观察改判为全称错误。

数值主比较按四项执行并留记录：①原主张及范围（总体/多数/全部/最大/并列）；②同组、同指标、同单位与方向的已读显示值；③计算工具的对齐比较结果、例外和并列；④该结果如何限定原句。复述已有比较也要执行，尤其不能从读对的一串值直接写成“每行/所有/均成立”。只算支撑主比较的行列；无法读清的值写未知，不补算。

把计算输入、真实来源、工具输出存入本次计算记录，并在 `visual_observations` 或相应问题中引用。普通逐组比较可用Python并留实际输出，不强塞入只支持有限运算的 `numeric_checks`。主体趋势成立但有局部例外时保留主旨，明确例外的行/指标和值；是否需要局部限定或作者确认取决于原句范围，不能自动判整表错误或要求重做图表。

## 4. 按问题规模给方案

每项用 `target_evidence` 定位真正承载内容的对象/区域。文字引用限定到单段落、单元格或实际子对象；同页多处证据用 `{source:"multiple_sources",refs:[...]}`，跨页用 issue.source_refs，不能跨格/跨对象拼出不存在的原文。漏读正文用具体 `region:` 与 description，不借页眉 ID。

- `action=local`：给操作 steps 和复核 check 即可。例如修复一个前景填充遮挡，应定位遮挡对象与受影响内容，保持已有有效结构。
- `action=revise`：给完整 `revision_plan` 的目标、结构、操作、字体协调和复核；说明谁是主信息，哪些组件承载哪些原材料。
- `action=split`：给完整 `revision_plan` 与 `split_plan`，至少两页的 title/message/content/layout/components，每页非空 source_refs，说明顺序和细节去向。多部分服务同一任务不自动拆页。
- 备用拆页用 `alternatives=[{action:"split",activation_condition,pages:[...]}]` 明确表示，pages 同样完整。自然语言中的“拆页”不触发强制方案；不能用“必要时拆页”代替条件与设计。

结构调整通过 `source_refs` 与 `content_disposition` 登记原内容保留、移新页、移备份或去重；保留关键数值、单位、限定条件、图子区归属和公式含义。引用存在不证明语义保真，逐项核对去向与新结论。用同一研究的已有材料；确有需要的缺失来源由作者提供，并给当前材料可行的替代路线。

字体先腾空间、去重复或重排，再按角色保持大且协调；关键符号与结果不能当脚注缩小。放大图表保持比例，考虑标题、公式、文字和边距共存；普通方案不要求精确坐标。必要参数放 `revision_plan.parameters`，对象值与 PNG 目测分开，不能把位图字高换算成准确 pt。尚未实施并渲染的方案注明待验证。

## 5. 导入与交付

以快照中的 `review_template.json` 写新鲜 schema v4 JSON，绑定 input_sha256、snapshot_id 与全部有效 PNG 哈希，覆盖所有原页。正式导入前清除 preparation_only 占位标记，同步顶层与逐页完成度、质量和阻塞项；每个结构方案的原来源都有对应去向。旧 v1–v3 仅可显式 `--legacy-review` 导入，不属于新版验收。

新快照启用 `render_fidelity_review_version: 1`，逐页填写 `render_fidelity` 的字形、符号、主图、动态字段核对与证据。只有实际画面 confirmed、核心检查完成才可完整判好/判坏；字段存在本身不证明实际看图。全部 complete/全部 failed/其余 partial 的整套状态须在记录、诊断与简报一致。

输出前交叉核对：描述与实际可见映射一致；操作指向真实内容；方案与原材料去向、来源及工具复算一致。必要修改没有被可选方向挤掉；核心未知与未完成检查如实保留。

运行 `python "<SKILL_DIR>/scripts/analyze_pptx.py" INPUT.pptx --out OUTPUT_DIR --review REVIEW.json`。作者先看精简 `report.md` 的整套判断、逐页结论与必要方案；`report-details.md` 提供 11 项检查和全部证据，机器 JSON 保留所有记录。

必要方案在作者简报中附对应 Tip 的短依据；完整11项留在详情。验证更新规则时冻结通用 Skill，再用没有页面答案提示的独立执行者实际看图；只复用相同 PNG 的旧判断或只重审已知失败页，不能称新规则已覆盖其余页面。

哈希与字段校验保证绑定、完整性及已登记有限运算，不能证明实际看图、图像语义、内容保真或修改效果。LibreOffice 与 PowerPoint 的字体/版式可能不同；静态材料不能确定动画和讲述节奏。
