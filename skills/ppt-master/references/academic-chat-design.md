# 学术报告：设计参考图 → 聊天确认 → 原生复刻

学术汇报的设计与制作规则。先读本文件，再按任务选择工作流。参考页和修改意见在聊天中确认；已确认的构图用于后续可编辑制作。

## 1. 适用范围与默认风格

- 学术汇报默认使用本包 `templates/styles/academic-research/templates/design_spec.md` 的表达方法和 `swiss-minimal` 视觉语言：浅底、深色正文、克制的强调色、清晰图表、稳定标题和页脚。读取这份学术风格文件；这是设计依据，不等于已安装一个带原型的模板。
- 沿用用户提供的学校/课题组模板和论文原图；不要把“学术”理解为满屏说明、没有插图或装饰一律禁止。机制图、案例图、对照图和有意义的背景可以丰富页面，必须服务于内容。
- 普通生成、Quick、美化和图片复刻均走“参考图确认后再写最终原生页面”。Quick 减少方案选项和说明，**不自动取消参考图确认**。用户本轮明确委托不再确认时，记录委托原话、适用页与范围；不要伪造逐页批准。已有图片被用户明确指定为最终复刻依据时，直接将该指定作为这些图片的确认来源，不再重复询问。
- Edit Native 保持稀疏修改：只设计/确认修改页，未修改页按原文档的对象身份透传；不要为应用本规则而重绘整套材料。模板的简报、原型、规格和预览也全部在聊天确认。

## 1A. 规划阶段先参考现有模板与资源

在逐页构图和生成参考图之前，按本次材料与页面任务查看已有资源，并将采用方式纳入方案。用户指定的模板、背景和样页优先；学术报告先读 academic-research 规范，再按需要查看相关 Layout、图表、表格和图标。使用 templates/README.md 与相关索引定位少量合适候选，不遍历所有素材，不要求凑齐每类资源。

- **实际查看再判断**：Style/Brand 阅读具体 design_spec.md；Layout/Deck 查看相关规范及拟用 SVG 样页；图表/表格查看相应 SVG，图标查看实际候选。涉及画面时调用图片查看工具检查；需要时将 SVG 或 PPTX 样页渲染为 PNG。仅浏览索引不能写成已经看过样页。
- **区分参考与安装**：说明借鉴的是配色字体、构图、图表表达、图标还是背景。自由设计可以借鉴局部，不等于安装模板或锁定结构；正式安装仍走当前路由的模板选择与安装规则。无需采用不合适的资源，也不为套模板改动事实、增加页面任务或把每页做成同一构图。
- **写进规划而非交付后补记**：Default 在 Stage-2 方案中简述主要资源与用途，并在 design_spec.md 的 §III 添加 `### Template and Resource References`，记录 `资源类别 | 实际查看文件 | 拟用页面与用途 | 采用方式与理由`。保留真正影响方案的未采用候选及原因即可；§VII/§VIII 继续分别记录图表/表格与最终图片资源，不重复建表。
- **落实到单页简报与生图**：reference_review/briefs/P01.md 等逐页注明相关参考文件、具体借鉴点和允许变化处。用于画面参考的实际背景、样页 PNG 应传入内置图像工具，并在 generation.references 记录；文字规范则转成具体设计要求，不能只把本地路径写入提示词。模板局部参考不替代完整 AI 参考页设计。
- **Quick 与局部修改**：Quick 同样在构图前定向参考相关资源，将简短选择说明保存在聊天及受影响页的简报，不新增根级 Design Spec/lock，不将参考发现变成模板安装或选择器。精确复刻不另换风格，Edit Native 仅为计划修改页参考资源，保留其他页面。
- **规划与实际使用分开**：规划写“拟采用”；交付按实际提示词、参考图片和最终对象说明“已采用/未采用/无法确认”。只有查过索引或打开过文件不等于最终使用。此步骤并入现有方案沟通，不增加一轮独立确认。

## 2. 全部确认在聊天内完成

使用聊天中的实际图片和自然语言反馈完成确认。网页可用于资料检索，不作为确认入口。

用聊天中的简短方案、表格、逐页图片和用户自然语言回复完成确认。图片必须实际显示，附页号、标题和版本；不能用一串文件链接代替展示。支持“P01/P03 通过，P02 改成上下布局”等局部反馈。无回复、工具成功、模型自评或参考图存在都不算批准。

Codex 可用本地绝对路径图片嵌入，或宿主的图片展示能力；其他 agent 使用实际支持的附件/图片输出方式。不可声称显示了宿主未展示的图片；不能显示时说明限制并交付可查看的图像附件，在确认前停止后续复刻。

## 3. 图像工具与科学内容边界

**参考页面默认由内置 AI 图像工具生成完整内容。** 标题、正文、数据标签、图表和机制示意都允许出现在参考图中；最终组件的可编辑性在批准后的原生复刻阶段落实。生成参考图时先读取 [单页简报与 AI 整页参考图](page-reference-generation.md)。最终资源 `image_usage: none` 或 AI 资源路径“不适用”，不能用来跳过参考页面生图。禁止的是未经授权的外部绘图 API，不是 AI 生成参考图。


- 生成、补绘、抠图、背景和复杂图案优先优先使用**当前 agent 实际可调用的内置图像工具**。Codex 使用环境提供的 image generation/editing 工具（例如 GPT Image）；按该工具自己的说明传入参考图。不要绑定某个会过时的模型版本或假定 Claude Code 一定有绘图工具。
- 无内置绘图工具或用户指定服务时，可使用其明确选定并配置的外部 API。通过 `scripts/image_gen.py --allow-api` 显式调用，先核对所选后端是否支持参考图和图片编辑；带背景的参考页逐页调用 `--reference-image`。配置只放本地 `.env` 或环境变量，不写入提示词和确认记录。`--render-md` 仍可离线使用。
- 工具返回的图像必须保存到项目的真实路径，记录工具、提示词、参考图、尺寸和来源。无法取得本地文件时如实阻塞，不编造下载或文件路径。
- 无可用绘图路径时，继续内容规划，并由用户选择提供参考图、跨工具生图或原生设计预览。API 参考页使用 `reference_generation: external_image_api`，记录真实 provider/model、调用来源和用户选择；不能标成内置生图。
- 照片、装饰插画与背景可为位图。论文证据图优先保留原图；数据图由可验证数据构造，公式来自原文。不能用图像生成模型臆造曲线、数值、坐标、引文或论文结论。示例中的人为数字要标“示意”，不能混入真实实验结果。

## 4. 设计规则（逐页应用）

先写本页核心任务、听众要带走的一句话、材料来源、主要视觉、阅读顺序和需要解释的图注。按整套“案例/动机 → 问题 → 方法 → 证据 → 总结”的论述关系设计，具体页数和章节随材料变化。

| # | 规则 | 设计时具体落实 |
|---|---|---|
| 1 | 每页字数不要太多 | 将长段落提炼为短句，解释进入备注/备份；用机制、对照、流程或案例呈现关系。不能删掉必要条件、单位和结论边界，也不要为少字把概念改得含糊。 |
| 2 | 一页只承担一个核心任务 | 明确本页回答哪个问题。问题、方法、实验和结论各自承担独立叙事任务时拆页；为同一比较服务的结果与一句解释可以同页。拆分方案逐页写标题、内容去向、结构、图表/图示组件、前后衔接，不写空泛的“建议拆页”。 |
| 3 | 标题要有意义 | 采用具体问题或有证据的结论，例如“校准后连续三轮保持改善”；“实验/结果/讨论”可作小章节标签，不能代替信息标题。证据不足时用问题句，不能把标题写成未经证实的强结论。 |
| 4 | 颜色不要太多太乱 | 一套语义配色，主次和强调清楚；同一方法跨页同色，颜色区分同时配标签/线型。按照含义使用颜色，不按颜色数量机械判错。 |
| 5 | 注意排版细节 | 对齐、留白、边距、字重、图注、图形比例统一；按内容权重分配面积。文字单调时用有意义的图示丰富；空得失衡时放大核心图/正文或重排结构，不塞无关图案。 |
| 6 | 用案例引出问题 | 新任务/新问题先给可理解的已有案例、输入输出或对照，让听众先看见困难，再给任务定义。案例可以在前页，不要求每页重复。没有可靠案例时提出需要的材料或明确标示的教学示意，不冒充论文实测。 |
| 7 | 先讲例子，再讲公式 | 先用输入→输出或一组受控示意解释直觉，再给公式、符号对应和它解决的障碍；纯推导/备份页可承接已有例子，不强塞新例子。不擅改公式含义。 |
| 8 | 用精炼语言阐述创新点 | 用“做法—解决的困难/价值”描述贡献，模块先总览再分别展开；实现细节进入后页或备注。不要凭文案创造新贡献。 |
| 9 | 让听众一眼看到重点 | 建立标题→主图/核心数据→一句解释的阅读路径；将真正的主比较放大和强调，让次要内容退后。每个对象都同样醒目会削弱重点。 |
| 10 | 实验多用图，少用大表格 | 可靠数值可用时，主动考虑柱状图做方法比较、折线图做有序轮次/时间趋势、散点图做关系；类别无序不要硬连折线。保留单位、基线、条件和真实尺度；没有误差数据不补造误差条。精确查值、小型消融/参数表仍可保留；大表移备份时登记完整去向。 |
| 11 | 总结回扣核心内容 | 归纳问题、核心做法与已有关键证据，强化最后印象；Thanks 可以附在总结后，或单独作已完成总结之后的结束页，不要求每个致谢页重讲一遍。 |
| 12 | 文字尽可能大且协调 | 按最终 PPT 的物理字号与投影阅读距离判断，先扩大正文、图注、轴标签，再协调标题。16:9 学术正文可从 24–30 pt、标题 32–44 pt、图注 18–22 pt 试起，均为设计起点；SVG px 不是 PPT pt。放不下先删冗余/改结构/拆页，不把所有字缩小；不能只把标题做巨大。 |

这 12 条是设计与理解判断依据，不是打分表，不要求每页命中所有规则。已经清楚的表格、公式页和优秀页面应保留，并可以明确写“无需修改”。先看整体内容、布局、结构与观感，再用坐标和字号定位修复，避免把用户报告写成参数审计。

### 单页内容蓝图（不是绘图提示词）

## 5. 执行代码：把确认设计变成真正的 PPTX

### 5.1 生成并确认每页参考图

1. 先按 [page-reference-generation.md](page-reference-generation.md) 写单页设计简报与完整生图提示词，将实际背景/风格图片传入选定绘图工具，默认生成带标题、文字、主图和图注的整页 PNG。不能因最终可编辑性、最终无 AI 位图资源或数据需精确，就静默改成 SVG→PNG。用户明确选择原生参考或已确认原始页面时如实记录其选择；精确图表可局部保留可靠原图/数据图，不替换整页设计路径。参考文件放在 reference_review/，批准前不写最终 svg_output/ 或导出生产 PPTX。
2. 主图、标签与数据必须和来源逐项核对。既检查单页，也看整套节奏、章节和案例→公式的关系；修复空旷失衡、单调、挤压、小字、过多任务和大表格。截图内部可辨认内容必须实际查看。
3. 按 page-reference-generation.md 的清单例子写 reference_generation 与每页 generation（实际工具、调用来源、提示词、参考图片及用途），并归档源材料；此决策独立于最终位图资源清单。旧 v1 清单可以读取，但不能把未记录生成方法的旧 PNG 自动称为 AI 图。模板原型同样先设计参考；原生稀疏编辑只展示修改页，透传页保持原对象。

清单示例和字段说明见 [完整生图流程 §5](page-reference-generation.md#5-目视核对记录并等待确认)。

4. `python "${SKILL_DIR}/scripts/reference_review.py" prepare "<project>" --pages "<project>/reference_review/pages.json"`。
5. 在聊天展示每一页实际图片及版本、核心任务和必要说明，等待用户回复。多页可按用户阅读能力分批展示；所有将导出的新设计页最终均须被覆盖。
6. 用户明确批准后才用 `record` 记录**用户原话**、页 ID、当前版本和本条消息来源（宿主无消息 ID 时用日期/轮次和原话定位）。局部通过只登记这些页；“有意见但先通过”的语义以用户明确范围为准。

```bash
python "${SKILL_DIR}/scripts/reference_review.py" record "<project>" --version 1 --pages P01 --decision approved --message "<本轮真实用户原话>" --message-id "<真实消息来源>"
python "${SKILL_DIR}/scripts/reference_review.py" check "<project>" --before-authoring
```

命令只是记录决策，不能证明人类身份；agent 必须核对真实对话。严禁把示例字符串、自动脚本、测试夹具或自己说的话当用户批准。测试中的模拟批准只能存在于明确标为测试的目录，不能进入用户交付项目。显式委托的原话可作为范围内的执行授权，使用 `--decision delegated`，必须如实标为委托而非用户已看图。

### 5.2 1:1 复刻与可编辑边界

通过确认后，参考图的构图、内容、换行、字号层级、配色、比例、裁剪、间距、图层与视觉重点成为**绑定设计**；Executor 不得换成更容易编码的模板或自行简化。仍用原有 SVG→DrawingML 原生转换器，而不是把整页图片塞入 PPTX。

| 组件 | 实现与验证 |
|---|---|
| 标题、正文、图注 | 原生文本框/段落/run；读取 PPTX 核对文字、换行、强调、字体与实际显示 |
| 几何图、流程图 | 独立原生形状、连接线，按需要分组；核对连接、层次、遮挡与对象可单独编辑 |
| 可可靠读取的数据图表 | 原生 Chart + 对应数据；表格为原生单元格。使用本包语义 JSON/marker 并显式启用 `--native-charts-and-tables`；核对缓存/工作簿、标签、单位、条件，不从生成参考图反推数据 |
| 公式 | 优先原生 Office Math；支持范围外保留精确原图并明确限制，不编造等价表达 |
| 照片、背景、复杂证据图 | 独立图片对象，可移动、缩放、裁剪；不能宣称内部文字、器官或曲线组件可编辑 |
| 不支持的对象 | 先明确保留/阻塞/可行替代范围，需要影响参考设计时回到用户确认，不静默扁平化 |

“1:1”是设计复刻目标，不是未经验证的像素一致承诺。字体光栅化、原生图表样式或不支持效果导致的实际偏差必须修正；无法消除的偏差在图上指出并取得用户接受。不能用“组件可编辑”替代视觉保真，也不能用“视觉像”替代原生对象。

### 5.3 导出、渲染、反馈

- 保留原有项目、模板、引用、公式、数据与质量门。默认与 Quick 都通过 `scripts/reviewed_export.py` 导出；其参数沿用 `svg_to_pptx.py`。它先核验参考图、蓝图、来源哈希、批准、页覆盖与顺序，并拒绝将字节相同的参考位图嵌回页面，再调用上游转换器。重编码截图不能仅靠哈希识别，仍必须做下述原生对象审计。原生透传项目的未改页不应被虚构为新生成参考：普通上游 roundtrip 工具继续负责其身份保护，聊天记录绑定修改页的已确认设计。
- 导出后必须重新读取真实 PPTX，检查页数/顺序/文字/数据/公式/对象类型；在可用的目标软件或真实 PPTX 渲染器中渲染**全部输出页**。不能用 SVG 预览冒充 PowerPoint 渲染。
- 每页将实际 PPTX 渲染与确认图并排展示/查看，重点核对重点、内容、结构、位置、裁剪、文字大小、中文与符号、遮挡和编辑性。可生成差分图辅助定位，但单个相似度分数不能证明 1:1 或学术正确。
- 当前页有明显偏差先修复其原生/SVG/资源来源，再导出渲染复查；不把已发现的同类缺陷复制到后页。保持已确认的其他页不变。不无限循环：同一故障完成两次有针对性的修复仍未解决，列出具体剩余偏差，在聊天请求用户取舍，不宣称通过。
- 用户改变参考图/蓝图或来源时，重新 `prepare`，只对受影响页面重新确认；不受影响页的有效批准可保留。计划变化涉及页数/顺序时同步全套映射。
- 交付 PPTX、实际逐页渲染、参考/成品并排图、页级设计与来源映射、修改记录、验证结果和明确的不可编辑范围。验证记录区分自动检查、实际目视复核、目标软件打开与实际编辑样例，没执行的项目写“未验证”。

## 6. 快速使用示例

用户：“用 PPT Master 把这份论文做成中文组会汇报。”

先在聊天给内容框架（每页一个核心任务，案例先行），默认推荐本包学术风格；框架确认后制作逐页参考图，在聊天显示并等回复。确认后逐页原生复刻，运行质量门、受控导出、实际 PPTX 渲染和对照。若用户只说“快速”，减少设计方向选择而仍保留参考图确认。若用户明确说“直接做，不用等我”，按真实委托执行，不能写成用户已经逐页看图批准。
